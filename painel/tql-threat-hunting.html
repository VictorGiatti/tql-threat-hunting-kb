TQL Threat Hunting — Base de Conhecimento

Consultas de caça a ameaças para o XDR Data Explorer (Trend Vision One). Busque, filtre por tática e copie. Ative o toggle "Use Trend Query Language" antes de rodar. Use + Adicionar hunt pra ir alimentando com as suas — ficam salvas aqui no navegador.

Lembretes de sintaxe e performance

  • Sempre que souber, especifique with (log_type="…", product_code="…") — são filtros "de graça" e deixam a query muito mais rápida.
  • Comece com janela de tempo curta: ago(1h) → ago(1d) → ago(7d). Use project cedo pra trazer só as colunas que precisa.
  • Ordene os filtros do barato pro caro: == e in antes de contains/matches regex.
  • Campo em array (ex.: tags): use has, não contains. Vários valores de uma vez: has_any (…).
  • Filtrar por coletor: além de pname, dá pra usar collectorName (ex.: collectorName == "Windows_OS").
  • Campos parseados do fornecedor: pegue subcampos com vendorParsed.<Campo> e converta com tostring(...), normalmente via extend — ex.: extend cat = tostring(vendorParsed.Category).
  • Não achou a coluna? Abra a tabela de schema no painel esquerdo do editor (busca os campos por log_type).
  • Terceiros (oficial): with (product_code="tlc", log_type="thirdparty") + where logRepoId == "…" (o autocomplete lista seus conectores). O jeito por pname também funciona.

Como "ir alimentando"

  • + Adicionar hunt salva a query no armazenamento do navegador — ela reaparece toda vez que você abrir este artefato.
  • Os seus hunts ganham a marca SUA e um botão Remover. Os 21 de base não podem ser apagados.
  • Pra não perder nada (limpar cache, outro computador): use Backup / Restaurar pra exportar o JSON. Se me mandar esse JSON, eu deixo os seus hunts fixos na base permanente do artefato.

Aviso: são consultas de exemplo. Nomes de campo variam por fonte/schema — valide no editor. Zero resultado num hunt também é resposta (não achou o padrão). Ajuste as janelas de tempo conforme o volume.
